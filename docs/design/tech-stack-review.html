Scope — Proposed Tech Stack

Keep the stack in architecture.md almost as written. The choices are well-matched to the real constraints (~5 users, one non-engineer owner, Claude Code as the implementer). Three small tweaks and one CI guard, below.

Recommendation TL;DR

Ship the doc's stack. Keep Gemini for extraction (free tier + cost wins at 5 users), flip email to Resend from day 1, and add a one-line CI grep to enforce the dependency rule. Everything else is right.

Stack, layer by layer

Layer Choice Status Why
Backend Flask + app factory Keep Small, readable, no bundled features you won't use. Django's built-ins are wasted when Supabase Auth + Alembic already cover their ground.
Templates / UI Jinja2 + Alpine.js Keep SPA rewrite is the biggest way to blow up a project this size. Server-rendered pages with pockets of Alpine are exactly the right ceiling.
DB + Auth Supabase Postgres + Auth Keep Only non-optional pick. Buys RLS, auth, email confirmation, password reset for free.
Multi-tenancy Scoped repositories + real RLS (authenticated role) Non-neg. The §5 correction to from-scratch.md is the most important thing in the doc. Do not relax this.
Migrations Alembic from day 1 Keep "Supabase owns the schema" is how dev/prod drift silently. Alembic is permanent (ADR 0005).
ORM SQLAlchemy + native uuid Keep Heavier than needed, but plays with Alembic and is the tool Claude Code writes best. Fine.
Domain layer Pure Python, no framework imports Keep Usually over-engineered for 5 users — here it's load-bearing because the value is the calculation engine. Justified.
PDF extraction PyMuPDF + 200-char scanned guard Keep Proven in SLATE. No reason to swap.
LLM Gemini (JSON mode) Keep Decided: free tier + cost wins at 5 users. Revisit only if extraction quality becomes the bottleneck (bad rows on real syllabi, not hypothetical concerns).
Email Resend (from day 1) Decided Resend chosen over Gmail SMTP. Free tier covers 5 users forever, better deliverability + logs, and Google is deprecating app-password SMTP anyway.
Interactivity (future) Alpine.js now, HTMX when it strains Decided Alpine for tab-switching today; adopt HTMX the first time an Alpine component needs server-driven partial updates (approval-row edits, Workload course filter).
Host Fly.io · min_machines_running = 1 Keep Single-machine pin is what stops the daily-digest scheduler from double-sending. That coupling belongs in the ADR, not in someone's head.
Testing Heavy pytest on domain/, light services, 4 Playwright flows Keep Distribution matches §3's insight. Don't let it drift toward E2E-heavy.
CI guard Grep on domain/ imports Add Cheapest insurance in the project against the layering rotting. See callout below.

The one thing to add: a CI guard

Enforce the dependency rule with a grep in CI.
The whole architecture rests on domain/ importing nothing of ours. Right now, that's enforced by convention — meaning one distracted PR undoes it. A ten-line GitHub Action makes it structural. 
grep -rE "^(from|import) (flask|sqlalchemy|requests)" scope/domain/ && exit 1 || true
0 matches — dependency rule intact

Wire it into the existing GitHub Actions workflow. Fails the PR if any framework import leaks into the pure layer. Same instinct as the RLS switch: turn a "we're careful" into a "it can't happen."
